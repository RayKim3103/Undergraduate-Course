## 핵심 요약

이 장은 조합논리를 실제 하드웨어 블록으로 구현하는 방법을 다룬다. 개별 게이트를 직접 조합하는 random logic에서 출발해 ROM, multiplexer, demultiplexer/decoder, PLA, PAL 같은 regular logic 구조로 확장한다. 마지막에는 tri-state output과 open-collector처럼 여러 출력을 하나의 선에 연결하기 위한 non-gate logic을 다룬다.

중요한 판단 기준은 다음과 같다.

- 설계 시간이 짧고 모든 입력 조합을 그대로 저장하면 ROM이 편하다.
- 여러 출력 함수가 product term을 공유하면 PLA가 유리할 수 있다.
- 속도와 면적을 줄인 제한 구조가 필요하면 PAL이 실용적이다.
- MUX와 decoder는 단순 선택 소자가 아니라 임의 Boolean function 구현에도 사용할 수 있다.
- Tri-state와 open-collector는 shared bus 구조를 만들 수 있지만, 동시에 여러 소자가 충돌하지 않도록 제어해야 한다.

## Random Logic과 Regular Logic

초기 디지털 설계에서는 표준 gate package를 조합해 원하는 함수를 만들었다. 이러한 random logic 방식은 NAND/NOR 네트워크로 mapping하고, package 수와 delay, fan-in/fan-out을 따져야 한다. 작은 수정도 배선과 게이트 선택을 바꾸게 되어 engineering change가 어렵다.

Regular logic은 큰 범용 블록을 사용해 설계를 단순화한다. ROM, MUX, decoder, PLA/PAL은 내부 구조가 규칙적이므로 설계자가 특정 gate 묶음보다 "주소 선택", "입력 선택", "product term 공유" 같은 높은 수준의 구조로 생각할 수 있게 해준다.

## ROM 구조와 조합논리

ROM은 완전히 decode된 AND array와 유연한 OR/output array로 볼 수 있다. 입력 address가 row를 선택하고, 선택된 word가 출력된다. Boolean function 관점에서는 모든 입력 조합에 대한 출력을 table로 저장한 lookup table이다.

ROM으로 조합논리를 구현하는 절차:

1. 입력 변수를 address line으로 둔다.
2. 가능한 입력 조합마다 ROM address가 하나씩 대응되도록 한다.
3. 각 address word에 원하는 출력 비트들을 저장한다.
4. 출력 bit width는 구현하려는 출력 함수 개수와 같다.

ROM의 장점은 최소화가 거의 필요 없다는 것이다. 진리표가 있으면 그대로 programming하면 된다. 특히 code converter처럼 많은 입력 조합이 실제로 쓰이고 product term 공유가 적은 문제에 적합하다.

단점은 입력이 하나 늘어날 때마다 필요한 row 수가 두 배가 된다는 점이다. 입력 수가 커지면 면적이 빠르게 증가하고, don't-care를 활용한 최적화 이득도 제한적이다.

## Multiplexer와 Selector

`2^n:1` multiplexer는 `n`개의 select 입력으로 여러 data 입력 중 하나를 출력에 연결한다. 2:1 MUX의 기본식은 다음과 같다.

```text
Z = A'I0 + AI1
```

4:1 MUX는 두 select 입력으로 네 data input 중 하나를 고르고, 8:1 MUX는 세 select 입력으로 여덟 data input 중 하나를 고른다. 큰 MUX는 작은 MUX를 계층적으로 연결해 만들 수 있다.

## MUX를 이용한 함수 구현

`2^n:1` MUX는 `n`변수 Boolean function을 구현할 수 있다. select 입력에 함수의 변수를 연결하고, data 입력에는 진리표 값에 따라 0 또는 1을 묶으면 된다. 이는 ROM처럼 lookup table 방식으로 동작한다.

변수가 `n+1`개 이상이면 일부 변수를 select로 쓰고 남은 변수는 data 입력 쪽의 0, 1, 변수, 보수 변수 형태로 연결한다. 예를 들어 4변수 함수 `G(A,B,C,D)`를 8:1 MUX로 구현하려면 세 변수를 select로 두고, 나머지 변수에 따라 각 data input을 `0`, `1`, `D`, `D'` 중 하나로 배치할 수 있다.

## Decoder와 Demultiplexer

Decoder는 `n`개의 입력을 받아 `2^n`개의 출력 중 하나를 활성화한다. Enable 입력이 있으면 전체 decoder를 켜거나 끌 수 있다.

예시:

```text
1:2 decoder
O0 = G S'
O1 = G S

2:4 decoder
O0 = G S1' S0'
O1 = G S1' S0
O2 = G S1 S0'
O3 = G S1 S0
```

Demultiplexer는 control signal을 decode해 한 입력을 여러 출력 중 하나로 보낸다. Boolean function 구현 관점에서는 decoder 출력이 minterm을 생성하므로, 필요한 minterm들을 OR로 묶으면 함수를 만들 수 있다.

## Decoder를 이용한 함수 구현

`n:2^n` decoder는 `n`변수 함수의 모든 minterm을 한 번에 만든다. 특정 함수의 ON-set에 해당하는 decoder 출력만 OR로 묶으면 해당 함수가 된다. 여러 출력 함수를 동시에 구현할 때도 같은 decoder 출력 minterm들을 공유할 수 있다.

큰 decoder는 작은 decoder를 cascading해서 만들 수 있다. 예를 들어 5:32 decoder는 상위 비트를 2:4 decoder로 먼저 decode하고, 각 결과로 3:8 decoder 네 개를 enable하는 방식으로 구성할 수 있다.

## PLA와 PAL

PLA와 PAL은 product term을 만들고 이를 출력 함수에 연결하는 programmable logic이다.

PLA:

- AND plane과 OR plane이 모두 programmable이다.
- 여러 출력이 product term을 공유하기 쉽다.
- 매우 유연하지만 구조가 크고 느려질 수 있다.

PAL:

- AND plane은 programmable이고 OR plane은 고정 또는 제한되어 있다.
- PLA보다 빠르고 작을 수 있다.
- 각 출력에 연결 가능한 product term 수가 제한된다.

ROM, PLA, PAL은 모두 regular logic 구조지만 프로그래밍 자유도가 다르다. ROM은 모든 minterm을 준비하고 출력 값을 저장한다. PLA는 필요한 product term만 만들고 여러 출력에 공유한다. PAL은 더 제한된 OR 구조로 실용성과 속도를 얻는다.

## PLA/PAL 설계 예제

Code converter 예제에서는 여러 출력 `W`, `X`, `Y`, `Z`를 최소화한 뒤 PLA 또는 PAL에 mapping한다. PLA는 product term 공유를 활용할 수 있지만, 출력 간 공유가 거의 없는 함수라면 큰 이득이 적을 수 있다. 반대로 ROM은 공유 여부와 관계없이 진리표만 있으면 구현이 가능하다.

Magnitude comparator 예제는 `EQ`, `NE`, `LT`, `GT`처럼 여러 출력 함수가 있는 회로를 PLA에 배치하는 과정을 보여준다. 이때 제한된 product term 수 안에 들어가도록 consensus theorem 등으로 식을 다시 정리해야 할 수 있다.

중요한 실무적 관찰:

- 주어진 PLA의 product term 수보다 필요한 항이 많으면 그대로는 mapping할 수 없다.
- 함수별 최소화가 전체 multi-output 최소화의 최적해와 다를 수 있다.
- 공유 가능한 product term을 찾으면 PLA 자원을 줄일 수 있다.

## ROM vs PLA vs PAL

ROM이 유리한 경우:

- 설계 시간이 짧다.
- 입력 조합 대부분이 의미 있다.
- 출력 함수 사이 product term 공유가 적다.
- code converter처럼 table 기반 문제다.

ROM의 문제:

- 입력 하나가 늘 때마다 address 공간이 두 배가 된다.
- 큰 입력 함수에서는 비효율적일 수 있다.

PLA가 유리한 경우:

- 여러 출력 함수 사이에 공유 product term이 많다.
- logic minimization 도구를 사용할 수 있다.
- don't-care를 적극 활용할 수 있다.

PAL의 문제:

- 출력별 product term 수가 제한된다.
- OR plane이 고정되어 있어 임의 공유가 어렵다.

## BCD to 7-Segment Controller 구현

BCD to 7-segment controller는 4개 입력과 7개 출력이 있는 대표적인 multi-output 조합논리이다. 0부터 9까지의 BCD 입력에 대해서만 segment 출력을 정의하고, 나머지는 don't-care로 둔다.

구현 선택:

- ROM: 진리표를 그대로 저장하면 되므로 빠르게 구현할 수 있다.
- PLA/PAL: don't-care와 product term 공유를 이용해 자원을 줄일 수 있다.
- Multilevel logic: 공통 중간식 `X`, `Y` 등을 만들어 팬인과 product term 수를 줄일 수 있다.

이 예제는 "논리 최소화 결과"와 "실제 programmable device 제약"이 다를 수 있음을 잘 보여준다. 어떤 PAL은 입력/출력 수는 충분해도 출력별 product term 제한 때문에 구현이 안 될 수 있다.

## Non-Gate Logic

### Tri-State Output

일반 논리 출력은 0 또는 1을 적극적으로 구동한다. Tri-state gate는 여기에 세 번째 상태 `Z`를 추가한다. `Z`는 high impedance 상태로, 회로적으로는 연결되지 않은 것처럼 동작한다.

Tri-state buffer는 output enable이 켜졌을 때만 0 또는 1을 출력하고, 꺼지면 bus에서 물러난다. 이를 이용하면 여러 소자가 하나의 bus를 공유할 수 있다. 단, 한 순간에 하나의 소자만 bus를 구동하도록 enable 제어를 정확히 해야 한다. 둘 이상의 소자가 동시에 서로 다른 값을 구동하면 bus contention이 발생한다.

### Open Collector

Open-collector gate는 출력을 낮은 값으로 끌어내릴 수는 있지만, 높은 값으로 직접 밀어 올리지는 못한다. pull-up resistor가 선을 high로 만들고, 어떤 gate든 low를 구동하면 전체 선이 low가 된다. 여러 출력을 하나의 선에 묶는 wired logic에 사용할 수 있다.
