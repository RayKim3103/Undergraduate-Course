# 07 유한상태기계

## 핵심 요약

이 장은 flip-flop과 조합논리를 결합해 유한상태기계(FSM)를 설계하는 방법을 다룬다. FSM은 현재 state와 입력으로 다음 state와 출력을 계산하는 순차 시스템이다. Counter는 FSM의 가장 단순한 예이고, vending machine, sequence detector, traffic light controller처럼 조건에 따라 상태가 바뀌는 제어 회로도 FSM으로 설계한다.

핵심 설계 흐름:

1. 명세를 이해한다.
2. State diagram 또는 state table로 추상 동작을 표현한다.
3. 필요하면 state minimization을 수행한다.
4. Symbolic state에 binary encoding을 배정한다.
5. Next-state logic과 output logic을 구현한다.
6. Timing과 reset, invalid state 처리를 확인한다.

## State Element 추상화

FSM 설계에서는 회로를 state register와 combinational logic으로 나누어 생각한다. Register에 저장된 값이 현재 state이고, 조합논리는 현재 state와 입력을 받아 다음 state와 출력을 계산한다.

이렇게 나누면 feedback loop가 register 경계에 국소화된다. 즉 순차회로 전체를 직접 feedback 회로로 분석하는 대신, clock edge마다 state가 갱신되는 추상 모델로 다룰 수 있다.

## Asynchronous Sequential Logic과 Synchronous Sequential Logic

Asynchronous sequential logic은 입력이 바뀌면 state도 clock 없이 변할 수 있다. 반면 synchronous sequential logic은 clock event에 맞춰 모든 state가 함께 갱신된다.

디지털 시스템 설계에서는 synchronous 방식이 일반적으로 더 안전하고 분석하기 쉽다. 모든 state transition이 clock period 단위로 진행되므로 timing methodology를 적용할 수 있기 때문이다.

## Counter as FSM

Counter는 정해진 state sequence를 반복하는 FSM이다. 출력이 곧 현재 state이므로 일반 FSM보다 단순하다.

대표 sequence:

- 3-bit up counter: `000, 001, 010, 011, 100, 101, 110, 111, 000, ...`
- 3-bit down counter: `111, 110, 101, 100, 011, 010, 001, 000, 111, ...`
- Gray code counter: 인접 state 사이에서 한 bit만 변한다.
- Ring counter: 한 개의 1이 register 안에서 순환한다.
- Johnson counter: ring counter에 inverter feedback을 추가해 더 긴 sequence를 만든다.

Gray code와 Johnson counter는 transition마다 바뀌는 bit 수를 줄여 glitch나 decoding 문제를 줄이는 데 유리할 수 있다.

## Counter 설계 절차

Counter 설계 절차는 FSM 설계의 축소판이다.

1. 원하는 count sequence를 정한다.
2. State transition diagram을 만든다.
3. State transition table을 작성한다.
4. State encoding을 정한다. Counter에서는 보통 state 자체가 binary 출력이다.
5. 각 flip-flop의 next-state input 식을 구한다.
6. K-map으로 next-state logic을 최소화한다.
7. Invalid state가 valid sequence로 들어오는지 확인한다.

예를 들어 D flip-flop을 쓰면 각 state bit의 다음 값이 곧 D 입력이다. 현재 state `CBA`와 다음 state `C+B+A+`를 표로 만든 뒤, `D_C = C+`, `D_B = B+`, `D_A = A+` 식을 구하면 된다.

## Self-Starting Counter

일부 counter는 사용하는 state보다 flip-flop encoding 공간이 더 크다. 예를 들어 3비트로 5개 state만 쓰면 나머지 3개 state는 invalid state가 된다. 전원을 켰을 때 회로가 invalid state에서 시작할 수 있으므로, 설계자는 결국 valid state sequence로 들어오도록 만들어야 한다.

Self-starting counter는 invalid state에서도 몇 clock 이내에 valid state로 이동한다. 이를 위해 don't-care로 두었던 state를 다음 state table에서 명시적으로 처리하거나, reset 회로를 추가할 수 있다.

## Reset

FSM은 보통 시작 state가 필요하다. Reset은 register를 특정 state로 강제한다.

- Counter에서는 보통 `000` 또는 sequence의 첫 state로 reset한다.
- FSM에서는 명세상 초기 상태, idle state, wait state 등으로 reset한다.
- Reset이 없으면 전원 투입 후 초기 state가 예측되지 않아 잘못된 sequence로 들어갈 수 있다.

## Catalog Counter와 Cascading

슬라이드는 74163 synchronous 4-bit up counter를 예로 든다. 이 카운터는 synchronous load와 clear 입력을 가지고, positive-edge-triggered flip-flop 기반으로 동작한다.

Cascaded counter에서는 낮은 자리 counter의 terminal count 또는 RCO 신호가 높은 자리 counter의 enable 역할을 한다. 낮은 4비트가 `1111`에 도달하면 다음 clock에서 높은 자리 counter가 증가한다.

Synchronous load와 clear의 장점은 state 변화가 clock edge에 맞춰 일어난다는 것이다. 특정 offset에서 시작하거나 특정 값에서 끝나는 counter를 만들 때, decode된 조건을 load/clear 입력에 연결해 원하는 sequence를 구성할 수 있다.

## 일반 FSM 모델

일반 FSM은 다음 요소를 가진다.

- 상태: `S1, S2, ..., Sk`
- 입력: `I1, I2, ..., Im`
- 출력: `O1, O2, ..., On`
- Next-state function: 현재 state와 입력에서 다음 state를 계산
- Output function: 현재 state 또는 현재 state와 입력에서 출력 계산

Register에 저장된 state bit가 조합논리의 입력으로 들어가고, 조합논리 출력 중 일부가 다음 state bit로 다시 register에 들어간다.

## FSM의 Timing

State time은 clocking event 사이의 시간이다. Clock edge에서 현재 입력이 sampling되고 state register가 갱신된다. 이후 조합논리를 거쳐 next state와 output이 안정된다.

FSM끼리 연결할 때는 한 FSM의 출력이 다른 FSM의 입력이 될 수 있다. Mealy 출력처럼 입력 변화에 즉시 반응하는 출력은 다른 FSM과 조합 feedback을 만들 수 있으므로 특히 주의해야 한다.

## FSM 기본 설계 접근

FSM 설계는 일반적으로 다음 5단계로 정리된다.

1. Specification을 이해한다.
2. FSM의 abstract specification을 얻는다.
3. State minimization을 수행한다.
4. State assignment를 수행한다.
5. Implementation을 선택하고 next-state/output logic을 만든다.

중요한 것은 처음부터 gate 식을 쓰지 않는 것이다. 명세를 state diagram, state table, input/output sequence로 먼저 표현한 뒤 회로로 내려가야 한다.

## Vending Machine 예제

Vending machine은 nickel과 dime 같은 coin 입력을 받아 일정 금액 이상이 되면 `OPEN` 출력을 내는 FSM 예제다.

설계 관점:

- State는 현재까지 누적된 금액을 나타낸다.
- 입력은 동전 종류 또는 동전 없음이다.
- 특정 금액에 도달하면 상품 배출 출력이 활성화된다.
- 출력이 state에만 의존하면 Moore machine, transition과 입력에 의존하면 Mealy machine으로 만들 수 있다.

State table을 만들고 binary encoding을 부여한 뒤, D flip-flop 입력식과 output 식을 K-map으로 구한다.

## Moore Machine과 Mealy Machine

Moore machine:

- 출력이 현재 state에만 의존한다.
- State diagram에서는 출력이 state bubble 안에 표시된다.
- 출력이 clock edge 이후 state 변화에 맞춰 바뀌므로 더 안정적이다.
- 같은 동작을 구현할 때 Mealy보다 state 수가 많을 수 있다.

Mealy machine:

- 출력이 현재 state와 입력에 의존한다.
- State diagram에서는 출력이 transition arc에 표시된다.
- 입력 변화에 즉시 출력이 바뀔 수 있어 빠르고 state 수가 적을 수 있다.
- 서로 연결된 FSM에서는 asynchronous feedback이나 glitch 위험이 커질 수 있다.

Synchronous Mealy machine은 Mealy 출력을 register에 저장해 output timing을 clock에 맞춘다. Moore와 Mealy의 장단점을 절충하는 방식이다.

## Moore/Mealy 변환과 Retiming

Vending machine 구현에서 Moore output은 state가 바뀐 뒤 조합논리 delay만큼 늦게 안정된다. Mealy output은 마지막 coin 입력이 들어오면 clock을 기다리지 않고 바뀔 수 있다. 이를 register output으로 retiming하면 외부에서 보이는 출력 timing을 더 예측 가능하게 만들 수 있다.

슬라이드의 변환 예제는 같은 I/O behavior를 유지하면서 내부 state와 output register 구조를 바꿀 수 있음을 보여준다.

## Traffic Light Controller 예제

Traffic light controller는 highway와 farm road가 만나는 교차로를 제어한다. Farm road에 차량 감지 입력 `C`가 없으면 highway가 계속 green이고, 차량이 있으면 highway green에서 yellow, red로 넘어가 farm road에 green을 준 뒤 다시 highway green으로 돌아온다.

설계 요소:

- Sensor input: farm road 차량 유무
- Timer input: yellow 또는 green 유지 시간이 끝났는지
- Output: highway/farm road의 green, yellow, red 제어
- State: highway green, highway yellow, farm green, farm yellow 등의 교통 상태
- Reset: 기본 highway green 상태로 복귀

이 예제는 실제 controller FSM에서 state diagram, state table, output table이 어떻게 연결되는지 보여준다.
